# 前后端对接状态

更新日期：2026-11-11。本轮根据实际 Controller、DTO、VO 和 Service 适配 Agent 问答，仅修改前端，不接入评测或同题对比。

## Agent 前端适配

- `/agentRun/add` 显式传 `executorType`，支持 `rag` 和 `agent`，默认 RAG。请求结果不明时复用完整原请求；主动重试使用当前模式、当前资料范围和新的请求键，并关联 `retryOfRunId`。
- 订阅新增的 `skill_selected`、`tool_started`、`tool_completed`、`tool_failed` 具名 SSE 事件，断线后复用 `/runEvent/list` 按序恢复；超过 100 条时连续读取至补发完成再判断终态。
- 技能只展示后端返回的选择结果：`paper-qa` / `paper-summary`。工具面板按 `callId` 合并调用，映射目前已注册的 `get_paper_metadata` / `search_paper_chunks`，展示耗时和失败错误码。未知工具名保留原名。
- 单篇资料下提供结构化总结快捷问题；多篇资料下提示当前总结限制，仍可正常问答。前端不模拟服务端的技能路由规则。
- 工具失败允许 Agent 继续处理；只有 Run 的终态决定问答结束。取消/超时等终态后，未收到工具结果的调用不再显示执行中。
- 页面刷新后恢复活动任务或最近一次任务的可用事件。`RunView` 不返回执行器类型，旧任务无技能事件时不推断模式；排队任务尚无事件时也无法从快照判断模式。
- 本轮不调用 `/agentRun/evaluation`，不展示质量评分、Token 成本或同题对比。

## 已接通的五个接口

| 接口 | 前端使用位置与行为 |
| --- | --- |
| POST `/api/paper/list/page` | 论文库、资料选择器、总览。按标题、作者、主题关键词、状态筛选，分页并保留跨页选择 |
| GET `/api/paper/get?id=` | 论文元数据、摘要、最新任务 ID、失败原因与 `canAsk`；聊天室提问前重新检查 |
| GET `/api/paperProcessingJob/get?id=` | 上传完成面板、阅读详情；4 秒轮询等待/运行中的任务，终态停止，失败时显示原因 |
| GET `/api/paper/file?id=` | 经当前登录 Cookie 获取 PDF 字节，PDF.js 渲染、翻页、缩放、跳转引用的物理页码 |
| POST `/api/sessionPaper/updateScope` | 完整资料集合与版本一次提交；新会话设置范围、已有会话合并资料、聊天室选择器确认 |

论文列表的状态为 `uploaded/processing/ready/failed`；处理任务状态为 `pending/running/completed/failed`。两个状态集合分别使用，不混淆。列表没有 `canAsk` 和摘要，前端不会自行推断这两个字段；详情返回的 `canAsk` 才用于判断当前索引是否可问答。

### 论文库与总览

- 标题、作者、主题筛选按后端 AND 规则组合，主题使用关键词输入，不伪造主题枚举。
- 列表展示标题（未解析时回退到原文件名）、作者、主题、物理页数、上传时间和处理状态。摘要位于详情页。
- 列表出现待处理/处理中的论文时每 5 秒刷新当前页；失败停止自动刷新并提供重试。查询切换和离开页面后丢弃旧响应。
- 总览使用分页返回的 `total` 展示全部论文、`ready` 数量、待处理加处理中数量、会话数量，以及最近四篇论文。
- `ready` 数量明确标注为“已完成处理”，不冒充 `canAsk=true` 的数量；不使用单页数据推算主题或全库页数。
- 上传后刷新真实列表；不使用回执缓存代替论文库。新论文不会自动加入已有会话。

### 原文与笔记

- PDF 通过 `/paper/file` 读取，不直接访问 COS URL；当前采用完整文件下载后本地渲染，未使用 Range 分段下载。
- 文件接口即使以 HTTP 200 返回业务错误 JSON，也能正确展示错误或处理登录失效，不将 JSON 当 PDF。
- 引用导航 `/library/:id?page=N` 使用物理页码；阅读器支持上下页、页码输入和缩放。PDF 资源随页面销毁释放，下载在路由变更时中止。
- PDF.js worker、CMap、标准字体和 WASM 均来自安装依赖、由本地站点提供，无外部 CDN。`predev/prebuild` 生成被 Git 忽略的 `public/pdfjs/`。
- 六字段笔记、版本冲突保护及 Markdown 导出保留。处理任务终态会刷新详情与 `canAsk`。

### 资料范围与问答

- 范围确认只调用一次 `updateScope`，传 `{sessionId,paperIds,scopeVersion}`，不串行调用单条接口模拟批量操作。
- 选择器支持分页浏览、四项筛选、跨页勾选、已选列表搜索分页、移除选择、确认空集合；取消/Esc 不保存选择，没有聊天室一键全选。
- 当前关系需要分页读取，因此在读取前后校验会话版本；若版本变化重新读取，避免拼接出不一致的范围。
- 409/40900 保留当前勾选并阻止继续保存；用户明确加载最新范围后重新确认。已有会话“加入论文”冲突时，由用户再次确认按最新范围做并集合并。
- 更新集合上限按后端约束为 100 篇；问答任务可能有更小的独立限制，最终仍由后端验证。
- 可以将处理中论文纳入会话，但全部详情 `canAsk=true` 后才能发送。索引就绪检查失败也禁止发送，并显示原因；发送前再次查询范围和详情，发现范围版本变化时要求重新确认问题。
- 历史消息、引用和活动 Run 的快照保留；已有 SSE/补发/幂等重试流程继续复用。
