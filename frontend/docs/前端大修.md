AgentPaperMate 前端聊天页面 UI 重构任务
一、任务目标
请对 AgentPaperMate 的 Vue 前端进行一次聊天页面 UI 重构。

目前页面存在一个比较明显的问题：聊天区域太小，AI 回答被左右侧栏、各种功能卡片、状态模块和辅助信息挤占，整体更像一个管理后台，而不是一个以 AI 对话为核心的论文研究工作台。

本次重构的核心目标：
1. 扩大聊天区域，让用户的问题和 AI 回答成为页面的视觉中心。
2. 减少不必要的小卡片、边框、说明文字和重复信息。
3. 将 Agent 执行过程、论文资料范围等辅助信息改为按需展示。
4. 优化 AI 回答的字体、行距、宽度和 Markdown 阅读体验。
5. 保留现有全部业务功能、API、SSE 流式响应和交互能力。
   请以成熟的 AI 研究助手产品为设计参考，整体风格简洁、现代、专业，适合长时间阅读论文和进行学术讨论。
   二、开始修改前的要求
1. 先检查项目目录，了解 Vue 版本、组件结构、路由、状态管理、CSS 方案和现有页面布局。
2. 找到 ChatPage、AppLayout、RunProgress 以及消息列表、输入框、引用证据等相关组件。
3. 结合现有代码分析布局问题，不要只修改表面 CSS。
4. 优先在现有组件基础上重构，避免无必要地推倒重写。
5. 如果当前目录只有 dist 打包产物，请先定位对应的 Vue 源码，不要直接把 dist 当成长期维护的开发入口。
   三、核心布局调整（最高优先级）
1. 取消聊天页面右侧常驻侧栏
   目前右侧存在：
- 围绕证据展开讨论
- 当前资料
- 其他辅助信息
  这些内容不应该一直占据聊天区域的宽度。

调整要求：
- 取消右侧常驻栏。
- 将资料范围、证据辅助信息等功能改为抽屉（Drawer）、弹出面板或按需展开区域。
- 用户点击对应入口时再显示。
- 默认状态下，聊天区域尽可能占据整个可用宽度。
- 不要因为取消侧栏而删除原有功能。
2. 左侧导航支持折叠
- 保留现有左侧导航功能。
- 增加折叠和展开能力。
- 折叠状态下仅展示图标。
- 展开状态下显示完整导航。
- 用户进入聊天页面后，可以选择折叠导航获得更多聊天空间。
- 导航状态变化时，聊天区域应平滑自适应。
3. 重新分配页面宽度
   以 1440px 桌面屏幕为参考：
- 左侧导航折叠后尽量控制在 60～72px。
- 聊天区域占据剩余绝大部分空间。
- AI 回答正文建议最大宽度为 1000～1100px。
- 不要再让右侧固定栏挤压聊天区域。
- 在较大屏幕上充分利用空间，在小屏幕上自适应。
  注意：AI 回答正文可以有最大阅读宽度，但聊天主容器不能被固定宽度限制。
  四、聊天消息展示优化
1. AI 回答
   这是本次重构最重要的部分。

目前 AI 回答字体偏小、内容区域偏窄，卡片边框较多，阅读体验不好。

调整要求：
- 正文字号：15～16px。
- 正文行高：1.65～1.8。
- 一级标题：20～22px。
- 二级标题：17～19px。
- 三级标题：15～17px。
- 代码块：13～14px。
- 引用来源：12～13px。
- 增加段落之间的合理间距。
- Markdown 列表、表格、代码块、数学公式应有良好的阅读效果。
- AI 回答采用宽幅阅读式布局，不要使用过窄的聊天气泡。
- 减少不必要的卡片背景和边框。
- 保留现有复制、重新生成、反馈等消息操作功能。
2. 用户消息
- 用户提问继续采用靠右的气泡布局。
- 使用浅色背景，与 AI 回答形成视觉区分。
- 字号建议 14～15px。
- 气泡宽度根据内容自适应，但不要过窄。
- 保留消息操作能力。
3. 引用证据展示
   引用是 AgentPaperMate 的核心功能，不能因为追求简洁而删除。

调整要求：
- 正文中的引用标记继续保留。
- 引用来源应与正文建立清晰关联。
- 默认采用紧凑的引用摘要。
- 点击引用后再展开详细证据。
- 详细信息包括论文名称、章节、页码、原文内容等现有支持的信息。
- 避免每条引用都生成一个占据大量空间的大卡片。
- 保留现有引用跳转、证据查看等功能。
  五、Agent 执行过程优化
  目前 Agent 执行过程展示过于占据聊天空间。

请重点检查 RunProgress 及相关执行过程组件。

调整要求：
1. Agent 正在执行时，可以展示简洁的实时执行进度。
2. 展示当前执行阶段和必要的状态信息。
3. 完成后默认折叠执行过程。
4. 折叠状态展示简洁摘要，例如：Agent 执行过程、已完成、4 次工具调用。
5. 用户点击后可以展开完整执行记录。
6. 展开后保留 Skill 选择、工具调用、检索结果、章节读取等现有执行信息。
7. 失败时仍然需要清晰展示错误信息和重试入口（如果原功能支持）。
8. 不允许为了减少页面内容而删除 Agent 的可观测性。
   尤其注意：执行中的状态展示和执行完成后的历史展示应该有所区别。
   六、输入框区域优化
   目前输入框周围堆叠了回答模式、模式说明、快捷提问、提示文字、草稿同步状态等多个模块。

请重新设计输入区域。

要求：
1. 输入框固定在聊天区域底部，支持合理的粘性定位。
2. 输入框高度适当增加，支持多行输入和自动扩展。
3. 回答模式（RAG / Agent）整合到输入框底部工具栏。
4. 模式详细说明放入 Tooltip 或帮助说明中，不要常驻占据空间。
5. 快捷问题只在新建会话、尚无聊天记录时展示。
6. 草稿同步状态不需要一直占据显眼位置，仅在同步失败时突出提示。
7. 保留附件上传、发送、停止生成、Enter 发送、Shift+Enter 换行等现有功能。
8. SSE 生成过程中，输入区域和按钮状态应正确变化。
   七、顶部区域优化
   目前页面标题、聊天室标题、资料范围等信息存在重复展示。

建议整合为一个紧凑的顶部区域：
- 当前会话名称。
- 当前选择的论文数量。
- 当前回答模式（可选）。
- 资料范围调整入口。
- 会话切换入口。
- 新建会话入口。
  要求：
- 不要使用多个大型信息卡片重复展示相同内容。
- 资料详情点击后通过抽屉查看。
- 保留现有会话管理、论文范围管理等功能。
  八、整体视觉设计要求
  请统一整个聊天页面的设计语言：
1. 简洁、现代、专业，突出学术研究氛围。
2. 以阅读体验为第一优先级。
3. 减少不必要的边框、阴影、背景色和嵌套卡片。
4. 不要每个功能都设计成独立的小卡片。
5. 统一圆角、间距、字体和颜色。
6. 合理利用留白，不要让页面显得拥挤。
7. 保留现有品牌主色，但避免大面积使用高饱和颜色。
8. 优先使用清晰的层级、字号和间距区分内容，而不是依靠大量边框。
9. 兼容桌面端和常见笔记本屏幕，做好响应式布局。
   九、功能兼容要求（非常重要）
   本次是 UI/UX 重构，不是业务逻辑重构。

必须保留：
- RAG / Agent 模式切换。
- 论文范围选择。
- 会话创建、切换和删除。
- 聊天消息历史加载。
- SSE 流式输出。
- 停止生成。
- Agent 执行过程和工具调用展示。
- Skill 相关功能。
- 引用证据展示及跳转。
- 文件上传。
- 消息复制、重新生成等现有操作。
- 草稿同步。
- 现有错误提示和加载状态。
  严格要求：
- 不修改后端 API 接口及请求参数。
- 不随意修改接口响应数据结构。
- 不破坏 SSE 事件解析及事件处理逻辑。
- 不改变现有业务状态流转。
- 不删除现有功能。
- 如果需要拆分组件，确保 props、emits、状态传递和事件监听正常。
- 不要为了实现视觉效果而使用模拟数据替换真实数据。
  十、最终验收标准
  完成后请逐项检查：
1. 进入聊天页面后，第一视觉中心必须是聊天内容，而不是功能卡片。
2. 取消右侧常驻栏后，聊天区域明显变宽。
3. AI 回答在常见桌面屏幕上具有良好的阅读宽度。
4. 正文字号和行距明显改善。
5. Agent 执行完成后默认折叠，不再挤占聊天历史。
6. 用户仍然可以展开查看完整执行过程。
7. 引用证据仍然可以正常查看和追溯。
8. 输入框不再被各种辅助模块挤压。
9. 左侧导航折叠和展开正常。
10. RAG / Agent 切换、SSE 输出、停止生成、历史会话等功能全部正常。
11. 不出现横向滚动条、布局错位、弹窗遮挡或输入框覆盖消息等问题。
12. 运行项目并检查控制台错误，完成必要的构建和测试。
    十一、执行方式
    请直接在现有项目中完成修改，不要只给我一份设计方案或 CSS 示例。

建议按照以下顺序执行：

第一阶段：检查现有代码，梳理聊天页面组件结构和样式依赖。

第二阶段：重构整体布局，优先解决左右侧栏挤占聊天空间的问题。

第三阶段：优化 AI 消息、用户消息、Markdown 和引用证据的展示。

第四阶段：优化 Agent 执行过程和输入框区域。

第五阶段：检查响应式布局，验证原有功能和 SSE 流式交互。

第六阶段：运行构建和必要测试，修复发现的问题。

完成后向我汇报：
- 修改了哪些组件和文件。
- 整体布局做了哪些变化。
- 哪些功能保持不变。
- 构建和测试是否通过。
- 还有哪些问题需要我确认。
  最终设计原则：默认只展示用户真正需要阅读的内容——问题、AI 回答和必要的引用证据。其他功能全部保留，但应该在用户需要时再出现。

不要为了展示功能而牺牲对话空间。AgentPaperMate 应该首先是一个优秀的论文 AI 对话工作台，其次才是一个功能丰富的 Agent 系统。
